## Problem 1 (Parity Sort)

### Review: Partition Operation

As we discussed in class, the quicksort algorithm relies on the `partition` operation to rearrange elements of an array in relation to the **pivot** element `P`.  After partitioning, the left partition contains all elements `≤ P`, and the right partition contains all elements `≥ P`.  Below is the implementation of `partition` we used in class.

```java
/// Applies the partition operation to the range `[start, end)` of the input `array`.
/// The partition is performed in-place, modifying the original array.
/// Returns the new index of the pivot element (which is in its final, sorted location!).
///     RUNTIME: O(n) Linear
///     REQUIRES: `length >= 2` and `0 <= start <= pivot < end <= length`
public static int partition(int[] array, int start, int end, int pivotIdx) {
  // swap the pivot with the first element
  swap(array, pivotIdx, start);
  // INVARIANT:
  //   start <= i < L    ==>  array[i] <= array[pivotIdx]
  //       R <  i < end  ==>  array[i] >= array[pivotIdx]
  int L = start+1;
  int R = end-1;

  // advance L and R, swapping elements as needed to maintain the invariant
  while(L <= R) {
    if      (array[L] <= array[pivotIdx]) { L++; }
    else if (array[R] >= array[pivotIdx]) { R--; }
    else {
      // both l and r are on the wrong side of pivot, so swap them
      swap(array, L, R);
    }
  }

  // after the loop, R = L-1
  // the partition boundary is between L and R
  // so, move the pivot into its final, sorted location (L1)
  int newPivot = L-1;
  swap(array, start, newPivot);
  return newPivot;
}
```

## Problem 2 (Selection)

The **Selection Problem** is concerned with selecting the `k`th smallest element from a set of `N` distinct numbers.

- **Input:** A set `A` of `N` distinct numbers and an integer `k`, with `1 <= k <= N`.
- **Output:** The element `x ∈ A` that is larger than exactly `k - 1` other elements of `A`.

For example, `Select(A=[6,24,7,8,1,4], k=3)` should return `6`, because there are exactly `k-1 = 2` numbers in the list smaller than `6`, namely `1` and `4`.

After partitioning, the pivot value has moved to `pivotIdx = 6`.  There are exactly `6` smaller elements, all located to the left, and exactly `3` larger elements, all located to the right.  The pivot is already in its **final, sorted location** even if the rest of the array is not yet sorted.

This observation is helpful for the **Selection Problem** because if we are looking for the `6th` smallest element, we can already stop and return the pivot value!  Otherwise, if we're looking for the `4th` smallest, we know it _must_ lie in the left partition.  If we're looking for the `8th` smallest, we know it _must_ lie in the right partition.  So, we can solve the **Selection Problem** by repeatedly calling `partition`!
