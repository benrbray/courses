## Problem 1:  Swap Pairs

Consider the following Java `class` representing **pairs** of values.

```java title="Problem1.java"
class Pair<L, R> {
  L left;
  R right;

  Pair(L left, R right) {
    this.left = left;
    this.right = right;
  }

  public L getLeft()  { return this.left;  }
  public R getRight() { return this.right; }

  @Override
  public String toString() {
    return "Pair[left=" + this.left +", right=" + this.right + "]";
  }
}
```

Add a generic method named `.swap()` to the `Pair<L, R>` class that returns a new pair with type `Pair<R, L>`. whose left and right values have been _swapped_ (right becomes left, left becomes right).  The example below demonstrates how a user might call the `.swap()` function, along with the expected output.

```java
Pair<String, Integer> before = new Pair<>("banana", 580);
Pair<Integer, String> after = before.swap();

System.out.println("Before: " + before);
System.out.println("After: " + after);
```

```console title="Expected Output"
Before: Pair[left=banana, right=580]
After: Pair[left=580, right=banana]
```

### Part B:  Implement `Comparable`

Many classes in Java implement the built-in [`java.lang.Comparable<T>`](https://docs.oracle.com/javase/8/docs/api/java/lang/Comparable.html) interface to impose a **default ordering** on their values.  This interface contains a single abstract method `compareTo`, as shown below.

```java
public interface Comparable<T> {
  /// if `this > other`, returns a positive number
  /// if `this < other`, returns a negative number
  /// otherwise, returns zero
  int compareTo(T other);
}
```

The static [`java.util.Collections.sort()`](https://docs.oracle.com/javase/8/docs/api/java/util/Collections.html) method can be used to sort any `List<T>`, provided that `T` is a class that implements `Comparable<T>`.  Add an implementation of `Comparable<Reference>` to the `Reference` class that works by comparing `authorLastName` first, then `year`, and finally `title`:

- If two publications have different authors, order them alphabetically by `authorLastName`.
- If two publications have the same `authorLastName`, order them chronologically by `year`.
- If two publications have the same `authorLastName` and `year`, order them alphabetically by `title`.

### Example:  `Comparator` Interface

In Java, a class may only provide one implementation for each `interface`, so our `Comparable<T>` approach will not work if we wish to sort the same data in two different ways.  Instead, there is a different interface named `java.util.Comparator<T>`, whose `compare()` method takes _two_ values of type `T` and compares them.

```java
interface Comparator<T> {
  /// if `left > right`, returns a positive number
  /// if `left < right`, returns a negative number
  /// otherwise, returns zero
  int compare(T left, T right);
}
```

As an example, we could define two different ways to sort a list of numbers by defining two classes `SmallestToLargest` and `LargestToSmallest` that implement `Comparator<T>` in two different ways.

```java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

public class IntegerComparatorExample {
  public void main() {
    List<Integer> numbers = new ArrayList<Integer>(List.of(5, 10, 4, 20, 3, 1));

    numbers.sort(new SmallestToLargest());
    System.out.println("SmallestToLargest: " + numbers);

    numbers.sort(new LargestToSmallest());
    System.out.println("LargestToSmallest: " + numbers);
  }
}

class SmallestToLargest implements Comparator<Integer> {
  public int compare(Integer left, Integer right) {
    return left - right;
  }
}

class LargestToSmallest implements Comparator<Integer> {
  public int compare(Integer left, Integer right) {
    return right - left;
  }
}
```

```console title=Output
LargestToSmallest: [20, 10, 5, 4, 3, 1]
```

### Part C:  Implement `Comparator<Reference>`

Every academic journal has its own preferred style (APA, MLA, Chicago, IEEE, etc.) that determines the order and appearance of bibliography entries.  Suppose we want to extend our implementation to support two different styles:

- **Style A:** References are sorted first by `authorLastName`, then by `year`, and finally by `title`.
- **Style B:** References are sorted first by `year`, then by `authorLastName`, and finally by `title`.

At the moment, our sorting logic is stored within the `Reference` class itself, as part of our implementation of the `Comparable<Reference>` interface.  This allows us to define a **only one** ordering per class, as Java won't allow a class to implement the same interface twice.
