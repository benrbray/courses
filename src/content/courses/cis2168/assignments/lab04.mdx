## Problem 2:  Circular Array Deque

A **double-ended queue ([deque](https://en.wikipedia.org/wiki/Double-ended_queue))** is an ordered collection that generalizes both stacks and queues.  A deque allows insertion and removal at both the *front* and the *back*.  The Java `interface` below lists the operations required by the deque abstract data type.

```java
public interface Deque<E> {
  /// Inserts a new element at the front of the queue.
  /// Requirement:  `element != null`
  void pushFront(E element);

  /// Inserts a new element at the front of the queue.
  /// Requirement:  `element != null`
  void pushBack(E element);

  /// Removes and returns the front element of the deque.
  E popFront();

  /// Removes and returns the back element of the deque.
  E popBack();

  /// Returns the front element without removing it.
  E front();
  
  /// Returns the back element without removing it.
  E back();

  /// The number of elements currently in the deque.
  int size();

  /// Returns `true` if the deque is empty, otherwise `false`.
  boolean isEmpty();
}
```

### Problem 3 (Single-Linked Queue)

Modify our `SingleLinkedList` implementation and all its methods to keep track of the `tail` node in addition to a `head`.  Then, use your modified linked list to implement a queue that has `O(1)` constant runtime for both `push()` and `pop()`.

```java
// SOLUTION
// To keep the solution simple, I created a new SLLQueue class
// that implements the Queue interface using a linked list internally.


public class SLLQueue<T> implements Queue<T> {

  private static class Node<T> {
    /// The data stored in this node, or
    /// `null` if this is the tail node.
    T data;

    /// A reference to the next node in the list,
    /// or `null` if this is the tail node.
    Node<T> next;

    Node(T data, Node<T> next) {
      this.data = data;
      this.next = next;
    }
  }

  //////////////////////////////////////////////////////////

  /// The first node in the linked list.
  /// Represents the "front" of the queue.
  private Node<T> head;

  /// The last node in the linked list.
  /// Represents the "back" of the queue.
  private Node<T> tail;
  
  /// The number of elements in the list.
  /// Equal to the number of `Node<T>`s in the list,
  /// not including the tail node.
  private int count;

  //////////////////////////////////////////////////////////
  
  SLLQueue() {
    this.head = null;
    this.tail = null;
  }
  
  //////////////////////////////////////////////////////////

  @Override
  public void enqueue(T elem) {
    // 0. Ensure the element is not null.
    Objects.requireNonNull(elem);
    // 1. Create a new node for this element.
    Node<T> node = new Node<>(elem, null);
    // 2. Insert into the back of the queue / tail of the list.
    if(this.tail == null) {
      // if the queue was empty, the new node
      // becomes both the head and tail
      this.head = node;
      this.tail = node;
    } else {
      // point the old tail to the new node
      this.tail.next = node;
      // make the new node the tail
      this.tail = node;
    }
    // 3. Increase the size of the list by one.
    this.count += 1;
  }

  @Override
  public T dequeue() {
    // 1. Remove the element at the head of the list (front of the queue).
    T removed = this.head.data;
    this.head = this.head.next;

    // If there was only one element in the queue,
    // now head and tail are both null.
    if(this.head == null) {
      this.tail = null;
    }

    // 3. Decrease the size of the list by one.
    this.count -= 1;
    return removed;
  }

  @Override
  public T peek() {
    return this.head.data;
  }

  @Override
  public boolean isEmpty() {
    return this.count == 0;
  }
}
```

### Problem 4

Add a new method to our `SingleLinkedList` implementation named `everyOther` that deletes every second element from the list.  The final list should look like `Node1 -> Node3 -> Node5 -> ...` with `Node2`, `Node4`, `Node6`, etc. deleted.  Your implementation should run in `O(n)` linear time, where `n` is the number of elements in the list.

```java
public void everyOther() {
  if(this.count < 2) { return; }

  Node<T> prevEven = this.head;
  int idx = 1;
  int newCount = count;
  while(idx < this.count) {
    Node<T> currentOdd = prevEven.next;
    Node<T> nextEven = currentOdd.next;
    // remove currentOdd by linking prevEven to nextEven
    prevEven.next = nextEven;
    // subtract one from the count
    newCount -= 1;
    // prepare for next iteration
    prevEven = nextEven;
    idx += 2;
  }

  this.count = newCount;
}
```

### Problem 5

Write a method `indexOfMin` that returns the index of the smallest item in a `List`, assuming that each item in the list implements the `Comparable` interface.

```java
public static <T extends Comparable<T>> int indexOfMin(List<T> list) {
  if(list.size() == 0) { return -1; };

  int minIdx = 0;
  T minT = null;
  
  int idx = 0;
  for(T t : list) {
    if(minT == null || t.compareTo(minT) < 0) {
      minT = t;
      minIdx = idx;
    }
    idx += 1;
  }

  return minIdx;
}
```

### Problem 6

The following review questions come from the _Koffman & Wolfgang_ textbook.

**What is the difference between the `size` and the `capacity` of an `ElasticArray`?**

The `size` is the current number of elements in the list.  The `capacity` is the total amount of space allocated for storing elements, but that space may be empty.  We always have `size <= capcity`.

**When we insert an item into an `ElasticArray`, why do we start shifting at the last element?**

If we started shifting from the first element, we would accidentally overwrite later ones!

**What is the advantage of a double-linked list over a single-linked list? What is the disadvantage?**

In a double-linked list, every node has a reference to both its `next` and `prev` node.  This allows us to easiy traverse the list both forwards and backwards.  Given a reference to an existing node in a double-linked list, inserting or removing that node can be achieved in constant time.  The disadvantage is that the extra `prev` pointer uses a small amount of extra memory per node.

**When would you choose an `ElasticArray` over a `LinkedList`?**

Accessing an element at a specific index in a linked list costs `O(n)`, because we must always start from the head and follow links until we reach the desired element.  Using an `ElasticArray`, we get constant-time access to any index.  So, if we frequently need to retrieve elements by their index, an `ElasticArray` is a better choice.

**Why is it more efficient to use an iterator to traverse a linked list?**

Calling `.get(index)` on a linked list takes `O(n)` runtime, so calling `.get(index)` in a loop would be quadratic `O(n^2)`.  The iterator is more efficient because it has internal state that keeps track of the current node we are visiting, and follows links using `.next`.  As a result, using an iterator to visit every element of a linked list only costs `O(n)` runtime.

**Explain the difference between a `Stack` and a `Queue`.**

A stack returns elements in *Last-In, First-Out* order.  A queue is *First-In, First-Out*.

**Write a method that takes a string as input and reverses the _words_ (not _characters_) in the string using a stack.**

```java
public static String reverse(String message) {
  String[] words = message.split(" ");
  Stack<String> stack = new ElasticArrayStack<>();

  for(var w : words) {
    stack.push(w);
  }

  StringBuilder result = new StringBuilder();
  while(!stack.isEmpty()) {
    result.append(stack.pop() + " ");
  }

  return result.toString();
}
```
