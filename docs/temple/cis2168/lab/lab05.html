Advanced Topic: Monoids

It is desirable for the binary operation and identity element to satisfy the definition of a mathematical monoid:

  1. The binary operation should be associative, apply(a, apply(b, c)) = apply(apply(a,b), c) for any three elements a, b, c.
  2. The identity element should be neutral. Combining an element e with the identity should not change the original element. In general, for all e, we want apply(e,1) = apply(1,e) = e.

As an example, addition is a binary operation (a,b) -> a + b.

  • Addition is associative, (a + b) + c = a + (b + c).
  • The identity element for addition is 1, since 1 + e = e + 1 for all numbers e.

Advanced Topic: Recursion Schemes

This idea of separating the recursive structure of a program from the actual operations is called factoring out recursion. Factoring out recursion is a useful design pattern when working with recursive data structures like trees. Languages like Haskell have a type system capable of describing generic recursion schemes for traversing recursive data structures.

Problem 3 (Postfix Expression Evaluation)

One of the most important applications of data structures is in the implementation of programming language compilers and interpreters. We are roughly following Chapter 4.4 of the Koffman & Wolfgang book, which presents the same information in a slightly different way.

Postfix Expressions

We normally write mathematical expressions using infix notation, like (5 + 3) * (4 / 2) + 9, where the mathematical operator appears between its arguments (also called operands). Infix notation is easy for humans to read, because we can easily scan left and right to understand the input to each operator.

A computer, however, processes the expression string one character at a time, from left to right. It will be easier to evaluate an expression if the operands always appear before the operator, as in postfix notation (also called Reverse Polish Notation). The table below compares equivalent postfix and infix expressions.

Postfix Infix
1 4 + 1 + 4
2 3 * 2 * 3
1 2 + 3 * (1 + 2) * 3
10 2 + 4 1 - * (10 + 2) * (4 - 1)

Evaluating Postfix Notation with a Stack

Expressions written in postfix notation can be evaluated using a single operand stack.

  • First, split the input expression (1 2 * 3 +) into individual tokens (like 1, +, etc.).

  • Next, process each token in the input expression from left to right.

    • If the token is a number, add it to the stack.

    • If the token is an operator like +, then:

      • Pop one or more values off the stack. (+ is a binary operator, so pop two values 1 and 2)
      • Compute the result of the operation. (compute 1 + 2)
      • Push the computed value (3) onto the stack.

Expr Data Type

The following Expr interface represents an expression. For the purposes of this problem, an expression is anything that can be evaluated to an integer.

In programming language terminology, a literal is the textual representation of a value. For example, in the postfix notation 3 2 +, the numbers 3 and 2 are both literals. Integer literals are the simplest possible expression – they simply evaluate to the number itself.

Binary Expressions

A binary expression is an expression that combines two other expressions. The BinaryExpr class has three fields:

  • String op is a string representing a binary operator (+, -, *, /).
  • Expr left is the first input to the binary operator.
  • Expr right is the second input to the binary operator.

Notice that BinaryExpr is a recursive data structure – left and right might also be BinaryExprs!
